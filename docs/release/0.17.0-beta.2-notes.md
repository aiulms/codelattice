# CodeLattice 0.17.0-beta.2 Release Notes

Date: 2026-09-13

Product version: `0.17.0-beta.2`

Status: external beta / daily-use candidate

## What This Release Is

`0.17.0-beta.2` is a bug-fix-and-quality release that clears the debt accumulated during `v0.17.0-beta.1`: it restores systematically missing Rust call edges (bin→lib), repairs `detect-changes --base-ref`, removes vendored-dependency diagnostic noise, closes the TypeScript/ArkTS graph-quality gap, and ships the Workbench desktop P0 plus a 4.4x engine speedup.

This release remains static-analysis only. CodeLattice does not compile, run tests, execute target project scripts, prove runtime reachability, or prove deletion safety.

## Headline Changes

- **Rust bin→lib CALLS edges restored (four-layer fix)**: packages with both bin and lib targets (i.e. most Rust applications) no longer lose cross-file call edges. Symbols in non-target-root files re-enter the crate-wide call index, `use <own-package>::x` no longer misclassifies as external crate, calls wrapped in field/reference/parenthesized/await/closure/try nodes are no longer dropped, and call extraction moved into a 16MB local rayon pool (the global pool's default 2MB stack overflowed on open-nwe/backend after deeper traversal). Measured: stock-core CALLS 30→9,357; open-nwe/backend CALLS 4,475→62,452; quality gates green.
- **detect-changes `--base-ref` repaired (three layers)**: illegal `{base}...` three-dot git invocation → `--merge-base`; `--merge-base` combined with diffMode=head no longer produces an always-empty diff; ambiguous multi-project workspace roots now report `Ambiguous` with guidance instead of crashing as not-compiled.
- **detect-changes docs-only fast path**: all-`.md` changes with no symbol impact cap riskLevel at `low` instead of noise-spiking to `high`.
- **Vendored dependency noise removed**: Rust file collection in `analyze` now skips dot-prefixed directories (`.tools`, `.cargo`, etc.), aligning with the inspect health-path semantics. Repositories containing vendored registries will see sourceFileCount/diagnosticCount drop significantly — this is a correction, not a regression.
- **CLI `workspace` subcommand**: `codelattice workspace --root <dir> [--compact] [--no-redact]` shares the MCP `codelattice_workspace_graph` implementation, completing the CLI/MCP symmetry for multi-project workspace structure.
- **7th quality gate aligned across languages (external_symbol_marking)**: all languages now expose 7 gates, with per-language evidence sources and honest not-tracked states for C/C++/Shell.
- **TypeScript/ArkTS graph-quality debt cleared**: TYPE_USE edges resolve to real type symbols through import binding / same-file symbol tables (dangling 526→0 on apps/desktop), TS/ArkTS gates grow from 3 to 6 (duplicate edges, dangling targets, calls endpoint integrity), ArkTS imports resolve through TsModuleResolver with `.ets` support, and `summary.diagnosticCount` is a real count instead of hardcoded 0 across TS/ArkTS/JS/C/C++/Python/Shell.
- **Project Understanding Workbench P0 (Tauri 2 desktop)**: local code-understanding workbench with a deterministic fact layer and explicitly-triggered model explanation — G6 graph with collision-safe force layout, Inspector with direct upstream/downstream and evidence navigation, model pool (Ollama / OpenAI-compatible, keys in the system keychain), evidence-grounded Chat, snapshot identity fixes, bounded query cache (8 snapshots / 512MB), and a 342.3MB aggregate memory baseline that passes the 512/384MB gate. See `docs/webui/workbench-user-guide.md`.
- **MCP memory cache P0 + parallel resolution (4.4x engine speedup)**: GraphView nodes/edges share `Arc<Value>` allocations, persistent cache schema v3 stores only analyze JSON, and import/call resolution runs per-file through rayon. Measured on open-nwe/backend (540 files, release build): engine total 4398ms→989ms, MCP cold cache-warm 6.8s→3.1s.
- **New diagnostic `codelattice_complexity_hotspots`**: identifies functions with the highest internal complexity (length + fan-in/out + async/unsafe modifiers), complementing `codelattice_risk_hotspots`. Full toolset grows from 49 to 50 tools; the AI toolset stays at 6 facade-first tools.
- **MCP `serverInfo.version` compile-time injection**: the advertised MCP server version can no longer drift from `workspace.package.version`.

## Install

After the GitCode Release page is published, install from the release tarball:

```bash
export CODELATTICE_TOOL_DIR="$HOME/.local/share/codelattice-tool"
tmp_dir="$(mktemp -d /tmp/codelattice-install-XXXXXX)"
git clone --depth 1 https://gitcode.com/aiulms/codelattice.git "$tmp_dir"
bash "$tmp_dir/scripts/install-release.sh" \
  --version v0.17.0-beta.2 \
  --install-dir "$CODELATTICE_TOOL_DIR"
"$CODELATTICE_TOOL_DIR/codelattice-mcp.sh" --self-test
```

## Build From Source

```bash
git clone https://gitcode.com/aiulms/codelattice.git
cd codelattice
bash scripts/install-mcp.sh --build
```

## Known Limitations

- Static results are investigation leads, not compiler/runtime/coverage proof.
- Dead-code and reachability signals are not deletion proof.
- Ask/workflow recommendations still require human or runtime verification before production changes.
- JavaScript dynamic import/require is diagnostic-only.
- Shell analysis never executes scripts and does not replace shellcheck.
- C/C++ analysis does not do full preprocessing, template instantiation, overload resolution, or virtual dispatch resolution.
- Python analysis does not execute Python, install dependencies, inspect virtual environments, or infer dynamic types.
- WebUI runner binds only to `127.0.0.1` and stores local snapshots under `.codelattice-webui/`.
